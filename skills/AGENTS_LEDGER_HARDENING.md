# Ledger hardening for human and agent maintainers

Read [HANDOFF](../docs/HANDOFF.md), [governance doctrine](../docs/GOVERNANCE_RESEARCH.md) and [ledger invariants L1–L17](../docs/LEDGER_INVARIANTS.md) before changing adapters/accounting. Workstreams: [36](https://git.cl8y.com/code/voting/issues/36), [37](https://git.cl8y.com/code/voting/issues/37), [38](https://git.cl8y.com/code/voting/issues/38), [39](https://git.cl8y.com/code/voting/issues/39).

* Never substitute `txs` decoded bodies for `tx_responses` execution results. Compare full SHA256 physical block transaction identities/order against executions; preserve original WASM ordinals before native metadata/emitter/registration filters; validate pagination completion before persistence. Empty responses and invalid schema differ.
* Never apply a delta when INSERT found a source identity already present. Verify duplicate payload equality. Snapshot baselines include the entire baseline block. Reject underflow and new events arriving behind existing checkpoints.
* Use `db::lock_chain` for accounting, registration insertion, reconciliation and rewind. Opening must acquire both in Terra/BSC order. Do not publish cursors/hashes outside their event transaction.
* BSC is chain 56 with 15-block confirmation policy. Adapter requests are bounded and provider errors are redacted. Browser balances continue to use the API.
* Terra RPC balance observations use explicit `TERRA_RPC_URLS`, same-provider status/block/ABCI body height and pre/post block hash. SDK base64 and Comet hex hashes normalize to the same byte identity. Do not accept stripped-header gateway heights inferred across load balancing. Bound aggregate block retention to 64 MiB.
* Preserve every nonzero cursor's forward continuity. A gap/fork does not authorize inventing balances. Explicit `--reconcile-live-baseline` or one-time deploy `LEDGER_RECONCILE_LIVE_BASELINE=true` creates a new durable eligibility epoch, preserving historical checkpoints; review orphaned advisory polls without modifying prior votes.
* Treat `/live` as liveness only. Admission uses complete canonical nondegraded checkpoints with age <=120s and tip lag <=2 Terra / <=17 BSC. Queue/chain failures must remain visible. Whole intent passes include SQL in the 60-second deadline; fresh `intents_ok` state has age <=120 seconds.

Verify with `cargo test --workspace --lib`, then isolated DB suites using explicit loopback `LEDGER_TEST_DATABASE_URL` with database `voting_test_*` and `LEDGER_TEST_ALLOW_DESTRUCTIVE=1`; never fall back to DATABASE_URL. Exercise HTTP adapters into actual Postgres, replay, boundaries, conflicting identities, rollback, provider cap/failover, continuity and worker isolation. Use new forward migrations, preserve frozen proposals and run secret scanning. Tests must not inherit production secrets. [Ops runbook](../docs/OPS.md) owns deployment/live checks; record actual evidence and leave criteria unchecked when unavailable.

Pin every physical writer connection to `pg_catalog,public,pg_temp`; pin migration creation to `public,pg_temp` and restore the writer path afterward. Test startup options and multiple concurrent pool connections against a legacy shadow table, including a newly opened replacement. Do not infer canonical storage from one successful migration connection or move/copy historical tables without actual schema/row/frozen-reference inventory. See [L10 trusted schema invariant](../docs/LEDGER_INVARIANTS.md#l10--least-privilege).

When normal startup would mutate unaudited legacy storage, use the explicit `LEDGER_INSPECT_STORAGE_ONLY=true` diagnostic release first. Read its single `VOTING_STORAGE_INVENTORY` marker; compare common-column mismatch counts as well as row counts and versions. `null` means unavailable, not empty or equal. Inspection runs read-only before migration and leaves readiness false; clear the flag only after inventory review. Never print rows, wallets, signatures, credentials or arbitrary indexer-state values.
