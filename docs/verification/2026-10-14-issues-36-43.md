## Implementation and invariants

| Area | Change and source of truth |
| --- | --- |
| Complete observations (#36) | Physical Terra block transactions must exactly match execution search results; original WASM ordinals remain stable across registration/filter changes. BSC observations require chain 56, complete validated log identities, pinned providers and bounded adaptive ranges. See [ledger invariants](../LEDGER_INVARIANTS.md) and [ledger agent guidance](../../skills/AGENTS_LEDGER_HARDENING.md). |
| Accounting (#37) | Per-chain accounting locks and one transaction cover events, balances and canonical cursor/hash. Duplicate payloads must agree; underflow and uint256 overflow fail closed. Registration is bound to an observed canonical block and cannot race an overtaken cursor. |
| Continuity (#38) | Durable epochs, bounded fork rewind, finality and fresh canonical checkpoints govern freeze eligibility. Reconciliation explicitly changes the baseline while preserving historical/frozen power. Native Comet ABCI response height and block hash bind Terra balance observations; LCD height guesses are forbidden. |
| Workers (#39) | Terra, BSC and intent workers are supervised independently. Intents have bounded concurrent work and timeouts. Liveness survives provider failure; readiness requires both chains plus a fresh successful intent heartbeat. |
| Signed lifecycle (#40) | Signed version 2 nonce/revision/title/hash approval, transactional compare-and-set, final acceptance-time TTL checks, immutable revisions and exact persisted response receipts. [API invariants](../OPERATOR_VOTING.md), [transactional agent guidance](../../skills/AGENTS_TRANSACTIONAL_VOTING.md), and [detailed lifecycle evidence](2026-10-14-lifecycle-40-42.md). |
| Deployment boundaries (#41) | One production application factory owns strict CORS including PUT, bounded peer quotas, authenticated shared actor quotas, safe errors and correlated request IDs. Forwarding requires verified exact ingress peers. Production builds reject development settings. |
| SQL privilege (#42) | Restricted API identity, schema-qualified definers with pinned search paths, granular grants and complete opened-content/identity immutability. Effective privileges, inherited roles, column grants and definer ownership are checked at startup. Destructive fixtures require a dedicated marked test database. |
| Browser/protocol (#43) | DOMPurify rendering boundary, authoritative server canonicalization, generated OpenAPI/TypeScript contracts and shared full v2 signing vectors. UI uses configured threshold, canonical content and stored certified poll weights; recorded ballots cannot prompt a second vote. [Protocol agent guidance](../../skills/AGENTS_PROTOCOL_SECURITY.md). |
